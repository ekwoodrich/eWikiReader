---
name: ewikireader-release
description: Create and verify an eWikiReader stable release through a labeled dev-to-main pull request, including signed APK and generated changelog validation.
---

Read root `AGENTS.md` and `docs/workflow-plan-v1.md`. A release request authorizes the normal PR/merge/publication steps; a request only to prepare a PR does not authorize merging it.

1. Fetch branches/tags, inspect the working tree and open PRs, and ensure intended work is committed on `dev`. Incorporate `origin/main` into `dev` if needed; preserve unrelated work. Review the entire `origin/main...dev` diff. Do not publish local feature work directly from `main`.
2. Choose the requested bump, defaulting to patch when unspecified. Use exactly one label: `release:patch`, `release:minor`, or `release:major` (`release` also means patch). Determine the expected next stable version from exact semantic version tags (`vMAJOR.MINOR.PATCH`) plus historical `vMAJOR.MINOR.PATCH-eink` tags; the latter are read-only compatibility history. Ignore `dev-*` prereleases and other tag formats. Include at least one meaningful conventional commit where there are changes to describe.
3. Push `dev`, create/reuse a PR with base `main`, head `dev`, and the chosen label **before merge**. Use a concise body file describing changes and verification. Check CI; when authorized, merge with `gh pr merge --merge`. Avoid squash/rebase, which discard dev ancestry and undermine commit-count version ordering.
4. Monitor the `Signed Build & Publish` run for that PR (`release.yml`). Build/signing must succeed before changelog/tag/publication. If it fails, inspect logs without exposing credentials, fix on a feature branch through `dev`, and avoid blindly rerunning after partial publication: first inspect existing tags, changelog commits, and releases.
5. Verify the expected `vX.Y.Z` stable tag, short title/filename with no `-eink`, latest-release status, generated `CHANGELOG.md` and release notes, and uploaded APK. Download the actual asset, verify it with `apksigner`, inspect package/version using `aapt2 dump badging` or `apkanalyzer`, and compare its SHA-256 checksum with the GitHub asset digest. Package must be `io.github.ekwoodrich.ewikireader`; release certificate must stay consistent with prior signed artifacts. A Play Protect scan is separate from signature verification.
6. Fetch/pull the bot's changelog commit on `main` and merge `origin/main` back into `dev` (fast-forward if possible). Push within the release request's scope, leave task changes clean, and report PR, run, release URL, version, and validation limits.
